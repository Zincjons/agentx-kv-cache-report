# 实验范围与结果解释

## 数据表示与公共部分

trace 提供规则分组、uid 前缀、相对时间和 stop；schedule 提供请求 ID、当天毫秒时间戳和请求内容摘要，没有用户 ID。flat 与 schedule 的请求字段相同但没有 timestamp。stats 的长度分位数来自抽样。

trace 没有保留 request_id，因此公共部分按模型、输入输出长度、完整有序哈希、流式标记、API 耗时逐日匹配。重复按出现次数处理，结合唯一时间锚点消歧。用户已知而 trace 具体位置不唯一时不伪造行号。

严格公共候选 211,553 条；排除 15 条无法确认具体对应关系的重复小请求后，可靠公共部分为 211,538 条、1,808,432,150 输入 token。公共请求对照采用同一分母。

## 已核对参考结果

| 口径 | 请求数 | 输入 token | 每日冷启动加权命中率 | 跨天保留 |
|---|---:|---:|---:|---:|
| AgentX，原会话和分支快照 | 98,827 | 21,635,381,376 | 98.015600%（会话口径） | 不适用 |
| Sage trace 全量，规则分组隔离 | 211,603 | 1,808,432,345 | 61.091304% | 不适用 |
| Sage 公共部分，用户＋模型历史 | 211,538 | 1,808,432,150 | 74.029399% | 74.123859% |

最后两行整数仍有差别：每天冷启动时共享历史多命中 9 个 token，连续三天多 3 个。该数据几乎全部输入来自一个用户标识，不宜推广为一般多用户场景。

规则 session、用户缓存域和真实任务不同。不同任务的公共系统提示词、工具定义和文档可产生有效命中；不能凭命中确认同一个任务。

## 初步请求关联

主方案在同用户同模型内搜索更早请求：至少延续其 1,024 token 完整块前缀，仅忽略实际不足 64 token 的最后半块；前驱已结束且距当前不超过 120 秒；输入至少增长 64 token。完整前缀最长优先，同等长度优先 tool_use，涉及多个既有候选组时拒判。

另有 512/2048 token、30/600 秒、必须 tool_use 的对照，以及 3 次时间打乱检查。主方案得到 6,594 个候选组、31,055 条归组请求，覆盖 14.68% 请求和 40.02% 输入 token。

未知请求按冷启动计分的全量场景值为 29.618912%。**它不是真实任务内命中率**；与用户域结果的差值中，83.08% 来自把未知请求计为冷启动。候选组允许分支，可以是真实任务片段，也可能有公共模板造成的错误关联。

真实顺序的请求覆盖率为 14.68%，三次时间打乱平均约 0.91%。这支持时间连续性信号，不是有监督标注的准确率或误报率。

## Cache-aware 与统计限制

`experiments.cache_aware` 跳过规则分组，直接读取 schedule，比较共享无限、LRU、轮询、随机和缓存前缀路由。需一起检查副本请求数及输入量；平局轮转不保证非平局流量均衡。默认路由探测上限 256 块，也不是最优路由保证。

- 计分后立即加入本次全部输入块；不模拟并发 KV 完成时间或吞吐。
- 无限历史不淘汰，LRU 则按给定块数淘汰；均未加入过期策略。
- 没有提示词/输出正文、真实 task_id、父请求 ID 或客户端 run 标识。
- think_time 可由相邻 t 和 api_time 复算，不提供独立任务身份。
- system_tokens、tool_tokens 全为零，不能据此认定没有系统提示词或工具。
- `experiments.schedule` 的历史字段名 `continuous_three_day_run` 指所选日期的连续重放；日期范围以 `--days` 为准。

精简整数参考保存在 `reports/reference_results.json`；大文件、逐请求明细和运维交接材料不作为代码示例提交。
